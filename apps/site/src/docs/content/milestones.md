The project was built in thin vertical slices: each milestone went through every layer and ended with something that runs, checked live. This page lists what is done.

| Milestone                   | What it delivered                                                                                                                                                                                                                                                                                                                                         |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Research and design**     | The architecture, the first decision records and the tracker                                                                                                                                                                                                                                                                                              |
| **Foundation**              | The monorepo and tooling, the Postgres schema with row-level security, the Hono API with sign-in and first-run setup, the web app shell, the Docker image, the self-host bundle and CI                                                                                                                                                                    |
| **First agent**             | The agent harness, the replaceable model gateway, durable runs on Inngest, web and memory tools with schema-checked calls, live chat with Activity and Settings, familiars and voices, learning after the run, and the evals                                                                                                                              |
| **Experience pass**         | The shell and command palette, chat with a live familiar loader, Markdown with sources and charts, Activity, Home, chats and history, memory review, toasts with Undo, and a phone pass                                                                                                                                                                   |
| **The computer**            | Our own sandbox image with a Linux user per agent and an egress proxy, the browser, shell and files tools, artifacts, watching and takeover, saved logins, approval cards and address provenance in tainted runs                                                                                                                                          |
| **Integrations and policy** | The MCP client with sign-ins kept in the database, a reviewed catalog, app tools from their schemas, Gmail on Google's own API, the full vault with rotation and the OS keychain, the full policy engine with rules, draft cards you can edit before approving, background token refresh, per-agent app grants, notifications, and a red-team mailbox set |
| **The team**                | Delegation and fork-join, agent messages and group chats with a leader, interrupts that steer, stop and set work aside, routines and quiet checks, reminders and tasks for later, skills, episodes and nightly memory tidy-up, agents as files, unread chats, the team screens and multi-agent evals                                                      |
| **Desktop**                 | A light desktop per agent watched over VNC, the agent's terminal on it, desktop apps through the accessibility tree with a screenshot fallback, Python with Word and Excel files, `files.send` and a Files section, desktop evals, and arm64 images                                                                                                       |
| **Teams and continuity**    | A chat record per agent so "continue" continues, stop replies and a budget warning, capability cards in every roster, the coordinator role, handoffs that pass results by name and show in the chat, and the step trail as a timeline                                                                                                                     |

Every milestone was checked live on a development stack, and the later ones in a fresh self-host bundle too. The [decision records](/docs/decisions) hold the reasoning behind each step.
